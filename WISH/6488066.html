API 参考手册

本文档详细介绍了 Wishtools 的核心类和 API 接口，适用于希望深入了解系统原理或进行二次开发的开发者。

1. 核心类概览

Wishtools 的核心逻辑通过以下继承链实现：

object
 └── Resolve (版本解析基类)
      └── Acquire (包获取类)
           └── Require (依赖处理入口)

辅助组件包括：

  • Solver: SAT 求解器 (pysat)
  • Syncer: 远程同步协调器 (High Availability)
  • DBManage: 缓存数据库管理 (SQLite)
  • Locker: 原子文件锁协调器

2. Resolve 类

路径: wish/src/wishapi.py

负责基础的版本解析、比较和区间计算逻辑。

核心数据结构

package_graph

存储依赖解析过程中的状态图。

package_graph = {
    # 已完全解析元数据的包版本
    "graphed": {
        "pkg_name": {
            "version_tag": {
                "req": [...], "ava": [...], "path": "/abs/path"
            }
        }
    },
    # 求解器访问过的候选版本列表
    "visited": {
        "pkg_name": ["1.0", "1.1", "2.0"]
    },
    # 待处理的条件扩展
    "pending": { ... }
}

核心方法

version_key(tags)

将版本字符串转换为可比较的元组列表。

  • 输入: "3.10.6.lin.0"
  • 输出: [(1, 3), (0, '.'), (1, 10), (0, '.'), (1, 6), ...]

resolve_tags(flag, tags, tags_list)

根据版本约束从列表中筛选符合条件的版本。

calculate_interval(int1, int2)

计算两个版本区间的交集。这是版本求解的核心基础。

3. Acquire 类

路径: wish/src/wishapi.py (继承自 Resolve)

负责包的元数据获取、AST 解析和外部组件加载。

核心方法

resolve_platform(args)

检查包是否满足当前的平台和架构约束。

  • 输入: ava 列表
  • 逻辑: 遍历 ava 定义的包（如 platform, arch），对比 Config.Platform 中的系统信息。

parse_argv(path, argv, extend=True)

解析 package.py 中的函数调用参数。

  • 机制: 使用 ast 模块进行静态分析。
  • 重要: 它不执行代码，只是提取 AST 中的函数调用节点。这意味着 package.py 中的动态逻辑（如 if）对 req/ava 等关键字无效。

resolve_cons(name, flag, tags, path)

解析指定包的版本约束，返回符合条件的路径字典。

4. Require 类

路径: wish/src/wishapi.py (继承自 Acquire)

这是系统的主入口类，负责协调整个依赖解析和执行流程。

核心方法

process_pkgs(args)

处理包列表的主逻辑。

1. 调用 resolve_pkgs 递归构建依赖图。

2. 调用 Solver 计算最优解。

3. 处理 pending 状态的扩展包。

exec_reqs()

按拓扑序（依赖顺序）执行已解析包的 package.py。这是环境生效的关键步骤。

5. Solver 类 (SAT 求解器)

路径: wish/src/wishapi.py

使用 pysat 库解决依赖冲突问题。核心思想是将依赖图转化为 CNF (合取范式) 公式，通过 MaxSAT 算法寻找权重最大的解。

核心方法

collect_solution(entry_names)

收集满足所有约束的最优解。

  • 策略: 渐进式求解 (Progressive Solving)。

1. Top 5: 先尝试每个包最新的 5 个版本。

2. Top 10: 如果无解，扩大到最新的 10 个版本。

3. Full: 逐步扩大直至搜索所有版本。

  • 返回: 成功时返回 {pkg: version} 字典，失败时返回 None。

collect_verbose_info(original_visited)

在求解失败时，输出详细的诊断信息。

  • 触发: 当 Config.VERBOSE == "+" 且 collect_solution 返回 None 时。
  • 输出: 打印所有已访问的版本及其具体的冲突原因（如 missing 依赖缺失, conflict 禁止规则触发）。

build_constraints(...)

将依赖关系转换为 CNF (合取范式) 子句。

  • 硬约束: 必需依赖、版本互斥、禁止约束。
  • 软约束: 版本偏好权重。

build_weights(...)

计算每个版本变量的权重。

  • 公式: (100 - pos) * 10000 + (100 - lvl) * 100 + rank
  • 优先满足入口包，其次满足浅层依赖，最后倾向于新版本。

6. Syncer 类 (远程同步)

路径: wish/src/wishapi.py

协调本地缓存与远程仓库的同步，支持高可用回退机制。

核心方法

sync_pkgs(path)

同步单个包。

1. 检查本地包 ETag。

2. 如果过期或缺失，从 S3 下载。

3. 解压并更新数据库记录。

first_api_client(method_name, *args)

高可用 API 调用包装器。

1. 尝试主 WISH_RESTAPI_URL。

2. 失败则依次轮询 WISH_RESTAPI_URL1 到 WISH_RESTAPI_URL10。

7. Client 类及子类

APIClient

REST API 客户端，负责获取包元数据及执行高级操作。

  • 使用 @lru_cache 缓存请求结果。
  • 支持 HTTP 连接池和重试。

llm_chat(data)

与 LLM 服务进行交互。

  • 输入: 包含聊天上下文的字典 data。
  • 输出: JSON 响应或流式生成器（如果 stream=True）。

exec_cql(cql)

执行 Cypher 查询语言 (CQL) 语句。

  • 输入: CQL 字符串。
  • 输出: 查询结果列表。

S3Client

MinIO/S3 客户端，负责包文件的上传和下载。

  • 支持断点续传（通过 Loader 类显示进度）。

8. Environ 类

提供对环境变量的增删改查操作，支持链式调用。


# 示例
env("PATH").insert("/bin").append("/usr/bin")
  • insert: 头部插入 (优先级高)
  • append: 尾部追加 (优先级低)
  • setenv: 覆盖设置
  • remove: 移除值
  • unload: 按前缀移除

9. 辅助类

DBManage

缓存数据库管理 (SQLite)，记录包的 ETag 和最后使用时间。

Packer

路径: wish/src/wishapi.py

负责包的压缩与解压操作。

  • Pack: 使用 7z 格式压缩目录。
  • Unpack: 解压 7z 格式包到指定目录。
  • 特性: 支持多线程读取输出流以显示实时进度条。

Locker

路径: wish/src/wishapi.py

提供基于文件的原子锁机制，用于协调多进程并发下的包下载和解压操作（避免"半下载"或"解压冲突"）。

  • 锁文件位置: 位于包根目录的父目录下。
  • 命名规则: .{tags}.{action}.lock
  • 例如: .3.10.6.lin.0.download.lock
  • 获取机制:
  • 使用 os.open(path, os.O_CREAT | os.O_EXCL | os.O_RDWR)。
  • 这是一个原子操作，只有文件不存在时才会成功。
  • 重试策略 (Exponential Backoff):
  • 初始等待: 1秒
  • 增长倍数: 2倍 (1s -> 2s -> 4s -> 8s)
  • 最大单次等待: 10秒
  • 总超时时间: 60秒 (超时后尝试强制删除旧锁)

10. 错误代码与诊断 (Error Codes)

当 Wish 退出时，它会返回以下错误代码。详细的故障排查步骤请参考 🔧 故障排查指南。

代码名称描述潜在根因

:---:---:---:---

1NO_PARAM未提供包名参数用户输入为空

2CONFIG_ERRORpackage.py 解析错误语法错误、引用未导入模块

3NETWORK_ERROR网络连接失败DNS 故障、API 服务宕机、离线模式误触

4SPECPATH_ERROR指定的本地路径无效路径拼写错误、缺少 package.py

5RESOLVE_ERROR无法解析依赖依赖冲突 (Ban)、版本不匹配、循环依赖

6PENDING_ERROR扩展包激活条件未满足ext 包的 ava 条件在当前上下文中为 False

255UNDEFINED未定义错误内部 Bug、未捕获的 Python 异常

11. 高级环境变量

这些环境变量通常用于调试或高级配置，不建议普通用户修改。

变量名描述
WISH_INHERIT_MODE继承模式开关 (New)。设置为 "1" 时，子进程保留父进程环境，不执行清理。
WISH_LOCK_MODE控制文件锁的行为模式。
WISH_DEVELOP_MODE启用开发模式。当设置为 "1" 时，优先从 WISH_DEVELOP_PATH 加载包。
WISH_OFFLINE_MODE强制离线模式。当设置为 "1" 时，禁止所有网络请求，仅使用本地缓存。
WISH_PACKAGE_EXTRA逗号分隔的额外包列表，用于强制启用特定的扩展包。
WISH_ALIAS_PREFIX内部别名环境变量的前缀，默认为 WISH_ALIAS_。
WISH_RESTAPI_URLREST API 服务地址。
WISH_STORAGE_URLS3/MinIO 存储服务地址。
WISH_PACKAGE_ROOT包安装根目录列表 (内部使用)。
WISH_PACKAGE_PATH第三方包搜索路径列表。
